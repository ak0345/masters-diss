# Atom-level guidance on frozen molecular generators — code

Everything needed to reproduce *When Does Atom-Level Guidance Steer a Frozen Molecular
Generator? A Cross-Architecture Study*.

This is code only. Trained weights, sampled molecules, diagnostic dumps, aggregated results
and rendered figures are all excluded deliberately. Every one of them is regenerated by the
pipeline below.

---

## What the study does

A pretrained molecular generator is frozen. A small guide network is trained on top of it, and
that guide may modify only the per-step atom-type logits. Nothing else about the generator
changes, including its 3D coordinate sampler where it has one. The question is when such local
changes translate into control over the properties of the completed molecule.

Three frozen generators are studied, all trained on GEOM-Drugs and sharing an atom vocabulary:

| leg | model | representation |
|---|---|---|
| `quetzal/` | Quetzal | 3D, autoregressive atom types plus per-atom coordinate diffusion |
| `molgpt/` | MolGPT | 1D, SMILES tokens |
| `g2pt/` | G2PT | 2D, graph-grammar tokens |

## Setup

```bash
conda env create -f environment.yml
conda activate quetzal
```

**RDKit is pinned at 2023.03.3 and the pin is a correctness requirement, not a convenience.**
Later versions change bond perception from 3D coordinates, which changes every validity,
stability and conversion-rate number the study reports.

Python modules live flat at the repository root and import each other by bare module name. Every
script must therefore either run from the repository root, or be invoked through
`scripts/common.sh`, which resolves paths relative to the root and exports `PYTHONPATH`.
Calling a script directly by path from another directory puts that script's own directory on the
import path instead of the root, and the imports fail.

Two conventions hold across every driver:

- `DRY=1` prints every command and runs nothing. Use it before anything long.
- Stages skip work whose output already exists, so an interrupted run resumes rather than
  repeating itself. `scripts/README.md` documents exactly what each stage checks.

## The guide architectures

Three single-objective architectures, plus composition as a fourth design. All are
zero-initialised, so each is an exact identity map on the frozen prior at step zero.

| run-name tag | class | equation |
|---|---|---|
| `base` | `LogitGuide` | `logits + g(h)` — the *residual* guide |
| `tempgain` | `TempGainGuide` | `logits/T(h) + gamma(h)*g(h)` |
| `hidden` | `HiddenGuide` | `proj(h + delta(h))` |
| `base_prior` | none | the unguided frozen prior — **not a guide** |

Composition trains one guide per leaf scorer of an objective, then mixes them at sampling time
under three operators (linear, product, harmonic), weighting each component by its own learned
partition function.

A run's directory name encodes its whole configuration:

```
sweep-<reward>-<guide>-<objective>-replay_<on|off>-b<beta>-s<seed>
```

which is what lets the aggregation scripts recover the sweep axes from directory names alone.

### Two traps worth knowing

**1. `guide_type` merges two populations.** The flip-diagnostic reports label `base` runs as
`guide_type = TempGainGuide`, because the two classes coincide at `T = 1`. **Group flip reports
by the guide tag in the run name, never by the `guide_type` field**, or two separately trained
populations silently merge into one. `results/tables/make_delivery_table.py` is the reference
implementation.

**2. Guided and prior dumps of the same seed are coupled.** A guided dump and the prior dump
carrying the same sampling seed are generated from a shared random stream, so 21--67 % of their
molecules are byte-for-byte identical. That is a real and useful measurement in its own right,
but it makes any *similarity-to-the-other-sample* statistic meaningless if the guided pool is
compared against its seed-matched prior while the null is compared against an independent one.

Measured that way, Quetzal's guided pool returns a nearest-neighbour similarity of 0.507--0.569
against a null of 0.366. Measured against an **independent** prior draw it returns 0.362--0.366,
i.e. no effect. An earlier reading of `comparison_figures/make_cmp06_nn_similarity.py`
concluded that Quetzal's guide concentrates its output; that conclusion was withdrawn.
`results/ablations/chemistry/analyse_chemistry.py` uses an independent reference for both guided
and null, and is the correct implementation. `make_cmp06_nn_similarity.py` carries a warning
block explaining the bias it exhibits.

Pairing is not itself a problem, and it is deliberate. It is what makes the flip diagnostics
work, and for a *difference of scores* it reduces variance the way a paired test does. It only
contaminates statistics that measure how similar one sample is to the other.

## Reproducing specific results

Each of these reads existing pipeline output and needs no GPU.

These scripts resolve their inputs relative to their own location, so run them where they sit.

```bash
# Table: terminal top-10 across the guide sweep
python results/tables/make_landscape_table.py

# Table: delivery and flip diagnostics by architecture
python results/tables/make_delivery_table.py

# The paired sign test over the sweep
python results/ablations/sign-test/sign_test.py

# RTB training-batch validity against guided improvement
python results/ablations/rtb-validity/extract_validity.py

# Chemistry-space statistics, each against an explicit null:
# identical-molecule fraction, scaffold overlap, nearest-neighbour
# similarity with bootstrap CIs and permutation tests, property marginals
python results/ablations/chemistry/analyse_chemistry.py

# Per-reward one-versus-rest k-NN separability
python results/ablations/chemistry/separability_per_reward.py

# Where the reward lives on the 1D and 2D priors: the atom tokens a guide
# edits, or the structural tokens it never touches. Emits the comparison
# table across all three architectures.
python scripts/make_atoms_vs_structure_table.py

# The Perindopril composition-weight sweep, once the sweep itself has run.
# Reports the sub-score frontier, nearest-neighbour similarity and novel-scaffold
# fraction against a matched unguided-prior control, and the hypervolume of the
# attained two-component front.
python scripts/analyse_peri_weights.py
```

Two of these need a GPU and a checkpoint before the analysis above can read them.

```bash
# atoms-versus-structure, per leg and per objective
python molgpt/molgpt_gfn/diag_atoms_vs_structure.py \
  --ckpt logs/molgpt-gfn/sweep-osim-hidden-db-replay_off-b10-s0/checkpoints/last.ckpt \
  --reward osim --n_t1 400 --n_t2 1400 --batch 200
python g2pt/g2pt_gfn/diag_atoms_vs_structure.py \
  --ckpt logs/g2pt-gfn/sweep-osim-hidden-db-replay_off-b10-s0/checkpoints/last.ckpt \
  --reward osim --n_t1 900 --n_t2 800 --batch 150

# the two-component Perindopril weight line, 11 points x 3 operators
NUM_GPUS=3 bash scripts/sweep_peri_weights.sh
```

`n` differs per leg because the two priors parse very different fractions of what they
emit. MolGPT parses about 93 per cent of a plain rollout but only 11 per cent of a
structure re-roll; G2PT parses about 22 per cent throughout. Both diagnostics count the
unparseable fraction rather than scoring it at the invalid-reward floor, so a valid
fraction below 1 is a measurement and not a failure.

**G2PT needs `transformers==5.16.1`**, the version recorded in its checkpoint config. It is
not in `environment.yml` because only this diagnostic imports it.

The two table scripts write into the manuscript source tree at `papers/current/src/`, which is
not part of this codebase. Either repoint their `OUT` path or place this tree beside the
manuscript repository. See `results/README.md`.

The atoms-versus-coordinates ablation does need a checkpoint:

```bash
SINGLE_CKPT=logs/quetzal-gfn/sweep-osim-hidden-db-replay_off-b10-s0/checkpoints/last.ckpt \
  bash scripts/07_ablations.sh single
```

## Pooling conventions

Every table and the sign test pool the same way: `beta` in {1, 10}, both replay settings and
both training seeds {0, 42}, giving eight runs per architecture-objective-reward cell.

The `beta = 100` stress runs exist **only for the hidden guide**, so they are excluded from
every pooled comparison. Including them would put a different set of runs behind each row.
